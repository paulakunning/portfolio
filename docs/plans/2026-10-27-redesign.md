# Portfolio Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current copy-of-WordPress look with the approved redesign: Figma-like hero canvas, scroll-driven projects reel, and new layouts for every page, without touching routing, i18n, content model (beyond `featured`), the contact Server Action or CI.

**Architecture:** Restyle the existing Server Components with Tailwind 4 and the new tokens. Interactive behavior lives in three new small client components (`HeroCanvas`, `ProjectReel`, `CopyEmailButton`, plus `FooterCta` for a pathname check) whose math sits in framework-agnostic modules (`src/lib/canvas.ts`, `src/lib/reel.ts`) with Vitest tests. Server-rendered markup is passed into client wrappers as `children` so content stays indexable and works without JavaScript.

**Tech Stack:** Next.js 16.4 (App Router, `cacheComponents`), React 19.3, TypeScript strict, Tailwind CSS 4, Vitest, Playwright + axe.

**Spec:** `docs/specs/2026-10-14-portfolio-v2-design.md` (sections 1, 4, 5 and 6 carry the redesign). Visual reference: the prototype in `~/Dev/portfolio-prototipo/` (`styles.css` holds every measure the spec does not fix). Serve it with `python3 -m http.server 8771 --directory ~/Dev/portfolio-prototipo`.

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing Next code (AGENTS.md). `cacheComponents` is on: `new Date()`, `Date.now()` and `Math.random()` in a Server Component fail the prerender.
- No new dependencies. No animation library.
- Server Components by default. Client components allowed: `SiteNav`, `ProjectFilter`, `ContactForm`, `HeroCanvas`, `ProjectReel`, `CopyEmailButton`, `FooterCta`.
- Every UI string comes from `src/i18n/dictionaries/es.ts` and `en.ts` (`en` is typed `Dictionary`, so keys must match). Copy is taken verbatim from spec §4 "Textos nuevos del rediseño" and "Hero".
- `prefers-reduced-motion: reduce`: nothing moves on its own (no drop-in, no pinned reel, no card reveal, no smooth carousel scrolling).
- No `scroll-behavior: smooth` anywhere, and do not add `data-scroll-behavior` to `<html>`.
- Colors only from the tokens in spec §6. Text on `primary-deep` uses `background` at ≥ 65 % opacity.
- axe: zero violations on every page in both languages (`tests/e2e/a11y.spec.ts`), no horizontal overflow at 360px.
- Code, comments and commits in English. Conventional Commits, no tool attribution lines.
- One PR per group below, each from an up-to-date `main` and targeting `main`. Never branch from an unmerged PR branch.

## Review Focus

1. **Viewport crosses 900px while the reel is pinned** (window resize, tablet rotation): the reel must drop back to the carousel with no stale inline `height` or `transform`. Test in Task 5.
2. **Landing on `/#sobre-mi` with a full page load** (shared link, refresh), not only client navigation: the About heading must end up at the top of the viewport even though the pinned height is measured after hydration. Test in Task 5.
3. **Clipboard unavailable** (permission denied, insecure context): "Copiar" must show the email visibly instead of failing silently. Test in Task 3.
4. **Switching project tabs while cards are mid-reveal:** no card may stay invisible. Test in Task 7.
5. **Touch-dragging a hero tile on a phone:** the page must not scroll while dragging a tile, but must still scroll when the finger starts on the hero background. Test in Task 4.
